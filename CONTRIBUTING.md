# Contributing

All changes to shared engineering standards, skills, and policies require review by the platform owner and at least one relevant domain owner.

## Change process

1. Explain the problem and affected repository cohorts.
2. Propose the smallest useful change.
3. Include examples of expected behavior and non-goals.
4. Test the skill/policy against representative repositories.
5. Document false-positive risks and rollback.
6. Update version/changelog notes where behavior changes.

## Skill authoring

Each skill must include:
- clear activation/use case;
- required inputs and assumptions;
- ordered workflow;
- expected output;
- safety boundaries and prohibited actions;
- validation checklist;
- examples where useful.

Skills should be focused and composable. Avoid duplicating the entire organization policy inside every skill; link to shared policies instead.
