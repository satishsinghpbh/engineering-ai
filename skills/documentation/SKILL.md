# Documentation workflow

1. Identify user-facing behavior, configuration, API, operational, and onboarding changes.
2. Locate the canonical documentation and avoid duplicate sources of truth.
3. Update setup steps, defaults, examples, permissions, failure modes, and troubleshooting.
4. Verify commands and examples where feasible.
5. Keep language concise and distinguish required from optional configuration.

Do not document behavior that the code does not implement.
